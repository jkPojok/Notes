Это проект, демонстрирующий микросервисную архитектуру на базе .NET (C#) с использованием современных подходов к разработке (CQRS, Docker).

Проект представляет собой бэкенд и фронтенд для создания, редактирования и управления заметками с разделением зон ответственности между сервисами.

Технологический стек
Язык: C# / .NET
Фреймворки: ASP.NET Core Web API, Entity Framework Core
База данных: MS SQL Server (2022)
Брокер сообщений: RabbitMQ
Архитектурные паттерны: CQRS (MediatR), Clean Architecture
Фронтенд: React.js
Инфраструктура: Docker, Nginx

Domain (Ядро): Содержит сущности (Entities), value objects и интерфейсы репозиториев. Не зависит ни от каких других слоев или внешних библиотек.
Application: Содержит бизнес-логику (Use Cases), команды и запросы (CQRS), а также интерфейсы для внешних сервисов. Зависит только от Domain.
Infrastructure: Реализация доступа к данным (EF Core), работа с RabbitMQ, внешними API. Зависит от Application и Domain (реализует их интерфейсы).
Presentation (API): Контроллеры ASP.NET Core, настройка DI, middleware. Зависит от Application.

Проект состоит из 4 независимых микросервисов и инфраструктурных компонентов.

1. Notes (Основной сервис заметок)
Сердце приложения. Отвечает за бизнес-логику работы с заметками.
Функционал: Создание, чтение, обновление и удаление (CRUD) заметок.
Особенности: Реализован паттерн CQRS с использованием библиотеки MediatR для разделения команд (изменение данных) и запросов (чтение). Использует Entity Framework Core для работы с базой данных.
Взаимодействие: Отправляет события (например, NoteCreatedEvent) в RabbitMQ для других сервисов.

2. NotesIdentity (Сервис аутентификации)
Отвечает за безопасность и управление доступом.
Функционал: Регистрация пользователей, вход в систему (Login), выдача JWT-токенов.
Особенности: Генерирует и валидирует токены. Обеспечивает защиту эндпоинтов других сервисов.

3. NotesUsers (Сервис пользователей)
Управляет профилями пользователей.
Функционал: Хранение и обновление информации о пользователях (аватар, настройки профиля).
Взаимодействие: Слушает RabbitMQ. Когда пользователь регистрируется в NotesIdentity, этот сервис получает событие и создает для него профиль.

4. NotesContracts (Общие контракты)
Библиотека классов (Class Library), не является запускаемым сервисом.
Функционал: Содержит общие DTO (Data Transfer Objects) и события, которые используются всеми сервисами для общения друг с другом. Это обеспечивает типизацию и убирает дублирование кода.

5. NotesFrontend (Клиентская часть)
Пользовательский интерфейс.
Функционал: Веб-приложение на React, через которое пользователь взаимодействует с системой.
Взаимодействие: Общается с бэкендом через Nginx

Инфраструктурные компоненты
Nginx: Выступает в роли Reverse Proxy. Маршрутизирует запросы от фронтенда к нужным микросервисам (например, /notesapi/ -> NotesApi).
MS SQL Server: Единая база данных для сервисов.
RabbitMQ: Брокер сообщений для асинхронного обмена событиями (Event-Driven Architecture) между сервисами NotesApi и NotesUsers.
